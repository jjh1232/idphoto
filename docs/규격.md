엔진은 `src/scripts/cropper.js` 한 곳이다.

## 규격표

| | | mm | 얼굴 규정 | strict |
|---|---|---|---|---|
| 한국 | 이력서 · 반명함 | 30×40 | 없음 (관행) | false |
| 한국 | 여권 · 주민등록증 · 운전면허 | 35×45 | 머리 위 3~5, 얼굴 32~36 | true |
| 미국 | 여권 · 비자 | 50.8×50.8 (2×2 in — 51 로 반올림하면 600dpi 에서 1205px 라 국무부 상한 1200 을 넘는다) | 얼굴 25~35, 눈높이 바닥에서 28~35 | true |
| 일본 | 이력서 (履歴書) | 30×40 | 없음 (관행) | false |
| 일본 | 여권 | 35×45 | 머리 위 2~6, 얼굴 32~36 | true |

**얼굴 크기 규정이 있는 건 여권·비자뿐이다.** 이력서는 규정이 아니라 관행이라
안내선을 흐리게 그리고 `strict: false` 로 구분한다. 규정인 것처럼 보이면 안 된다.

**미국만 눈높이로 잰다.** 바닥 기준이라 위에서 재는 값으로 뒤집어 그린다.
나머지는 「머리 끝 + 얼굴 길이 = 턱」 이라 띠 두 개가 나온다.

## `strict` 는 안내선 굵기가 아니라 **무엇을 금지하는가** 다

프로토타입에서는 `strict` 가 안내선을 진하게 그리는 용도였다. 실제로는 그보다 큰 것을 가른다.

**한국 외교부:**

> 사진 편집 프로그램, 사진 필터 기능 등을 사용하여 임의로 보정한 사진
> (AI 를 활용한 편집·가공·합성·창조 제작물 **포함**)은 허용 불가
>
> 사진 편집 프로그램으로 기존 배경을 지우거나 인물을 흰색 배경에 합성한 사진은
> 제출할 수 없습니다.

**미 국무부**는 2026-01 부터 AI 로 생성·보정된 사진을 유예 없이 자동 반려한다.
픽셀 아티팩트와 메타데이터로 검출한다. 배경 제거·교체도 「디지털 변경」으로 보고,
안내는 **올바른 배경에서 다시 찍으라**고 말한다.

여기서 두 가지가 따라온다.

- **금지 대상은 「AI」 가 아니라 「소프트웨어로 바꾸는 것」 이다.** 손으로 브러쉬를
  칠해도 결과가 합성이면 똑같이 반려다. AI 를 피해서 통과할 방법은 없다.
- 그래서 `strict: true` 규격에서는 **밝기·대비를 잠근다.** 켜둔 채로 내보내면
  화면으로는 멀쩡해 보이는데 제출처에서 튕긴다 — 눈으로는 못 잡는 종류다.

배경 교체를 나중에 붙인다면 같은 플래그에 물린다. `strict: false`(이력서·履歴書)
에서만 열고, `true` 에서는 잠그고 **왜 잠갔는지 화면에 적는다.** 잠금만 걸고
이유를 안 적으면 고장으로 읽힌다.

## 다시 알아내려면 오래 걸리는 것

### 캔버스가 만든 JPEG 은 72dpi 다

`canvas.toBlob('image/jpeg')` 는 JFIF 머리의 해상도를 **1×1, 단위 없음**으로 적는다.
인쇄 프로그램은 이걸 72dpi 로 읽는다. 300dpi 로 뽑아도 인화하면 크기가 네 배로 나온다.
**화면으로는 멀쩡해 보인다** — 픽셀 수는 맞기 때문이다.

픽셀은 그대로 두고 머리의 숫자만 고친다.

```
 0  FFD8          SOI
 2  FFE0          APP0
 4  길이(2)
 6  'JFIF\0'(5)
11  버전(2)
13  단위           1 = 인치당
14  가로 해상도(2)  big-endian
16  세로 해상도(2)
```

`stampDpi()` 가 이 여섯 바이트만 고친다. **머리 모양이 다르면 손대지 않는다** —
어설프게 고치면 파일이 아예 안 열린다.

### 휴대폰 사진은 눕혀져 있다

EXIF 회전이 걸린 채로 오는 게 많다. `createImageBitmap(file, { imageOrientation: 'from-image' })`
로 받으면 세워진 상태로 들어온다. 이걸 빼면 옆으로 누운 증명사진이 나온다.

### 화면과 결과가 어긋나는 사고 — 두 번 막았다

**1차(프로토타입).** 자르기 코드를 화면용과 저장용으로 따로 두면 조용히 어긋난다.
그래서 `paint()` 하나를 배율 `k` 만 바꿔 두 번 쓰게 했다.

**2차(여기).** 그런데 그 `k` 를 **가로 기준 하나로만** 계산하고 있었다.
화면 틀은 `round(420 × w/h)` 로 반올림되고 출력은 `round(mm/25.4 × dpi)` 로 반올림되는데,
두 반올림이 같은 비율로 떨어지지 않는다. 그래서 세로 배율이 미세하게 달랐다.

| 규격 | 가로 배율 | 세로 배율 | 어긋남 |
|---|---|---|---|
| 35×45 300dpi | 1.26300 | 1.26429 | 0.54 px |
| 35×45 600dpi | 2.52905 | 2.53095 | 0.80 px |
| 51×51 (정사각) | — | — | 0 px |

0.8px 이라 눈에는 안 보인다. 다만 이건 **틀을 사진 끝까지 당겼을 때 아래쪽에
흰 줄이 남을 수 있다**는 뜻이고, 「여백이 생기면 그건 결과물의 구멍이다」 라고
적어둔 바로 그것이다.

고친 방법: 자르기 상태를 **이미지 좌표계**로 들고 있는다.

```
cropH   잘라낼 높이(원본 px). 폭은 w/h 비율로 따라간다 (반올림 전 값)
cx,cy   그 조각의 한가운데
```

화면은 그 조각을 캔버스 크기로, 저장은 같은 조각을 출력 크기로 그린다
(`drawImage` 의 source-rect 형태). 배율을 각자 계산할 일이 없어져서
어긋날 자리 자체가 없다. 정사각(51×51)에서 원래도 0px 이었던 게 힌트였다 —
비율이 딱 떨어지면 안 어긋났다는 뜻이니까.

## 아직 안 되는 것

| | |
|---|---|
| 얼굴 자동 맞춤 | 지금은 안내선만 그리고 사람이 맞춘다. MediaPipe BlazeFace(224KB)면 규정 수치에 맞춰 자동으로 잡을 수 있다. **전 규격에 쓴다** — 자르기와 위치 잡기는 편집이 아니다 |
| 배경 흰색으로 | MediaPipe SelfieSegmenter(243KB). **`strict: false` 에서만** (위 참고) |
| HEIC (아이폰 기본) | 사파리 말고는 브라우저가 못 읽는다. 지금은 「열지 못했습니다」 로 떨어진다 |
| 인화용 시트 | 4×6 인치에 여러 장 깔아주는 것. 동네 사진관에 넣는 실제 방식이다 |
| 여러 규격 한 번에 | 30×40 과 35×45 를 같이 뽑기 |

모델을 붙일 때 라이선스를 확인할 것. **RMBG(BRIA)는 비상업 전용이라 쓰면 안 된다** —
품질로 제일 먼저 눈에 띄는데 애드센스가 붙은 사이트에서는 위반이다.
MediaPipe 는 Apache 2.0 이라 괜찮다.
